\section{An Extension for Stochastic Simulation}\label{appendix:idle}

This appendix presents an extension of the cGLP transition system that is not part of the language.  A program that does not use it computes exactly as it does without it, and nothing elsewhere in this paper depends on it.

A Gillespie-style stochastic simulation draws which event happens next, and at what simulated time, and the drawing is done by a monitor written as an ordinary GLP program.  Machine steps carry no simulated time, so the monitor may draw only where no reduction, communication or cold call is possible: every event of the simulated system has been taken up, and the next one is the monitor's to choose.  A program has no way to learn that, since no goal of it is about the configuration it sits in.  The extension supplies one.

\begin{definition}[Idle Transition]
\label{def:idle-transition}
The \temph{idle extension} of a cGLP transition system (Definition~\ref{def:cglp-ts}) adds to $\calT$ the transitions $(G, \sigma) \rightarrow (G', \sigma')$ satisfying:
\begin{itemize}
    \item \textbf{Idle:} there exists a unit goal $A = $ \verb|when_idle|$(W) \in G$ such that no Reduce and no Communicate transition of $(G, \sigma)$ exists, $G' = G \setminus \{A\}$, and $\sigma' = \sigma \circ \{W := \mathtt{idle}\}?$
\end{itemize}
Two Idle transitions are equivalent under ${\sim}$ iff they remove the same goal, by identity (Definition~\ref{def:goal-identity}).
\end{definition}

The type of the goal's argument is \verb|Idle ::= idle|, a constant type, so a reader of it may occur more than once~\cite{shapiro2026types}.

A cGLP configuration changes only by a transition of its own, so a configuration in which only Idle transitions exist stays so until one of them is taken.  Monotonicity (Proposition~\ref{prop:glp-monotonicity}) therefore holds of the extension as it stands: an Idle transition available at one step of a proper run has either been taken by a later step, or is available still.  Computation is deduction (Proposition~\ref{prop:cglp-deduction}) and SO preservation (Proposition~\ref{prop:so-preservation}) are untouched, the transition adding no clause and assigning one constant, and every run of the extension is safe, so correctness is again liveness: a run that reaches a configuration with nothing else to do takes the Idle transition.

In maGLP the machine is an agent, and an agent's configuration is changed by the transactions of others: \emph{Communicate $p$ to $q$} and \emph{Cold-call $p$ to $q$} both change $c_q$ without $q$ taking a transition of its own.  An agent with nothing to do may therefore have something to do a moment later, with no transition of its own in between, and Monotonicity does not extend to \verb|when_idle| there.  What the goal reports is the agent's own machine at the moment it is taken, which is what a grassroots system can report: there is no global configuration to consult, and no agent may wait on one.
